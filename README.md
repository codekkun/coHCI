# 水果忍者 Web 版 - 项目文档

## 📋 项目概述

**水果忍者 Web 版** 是一个基于人机交互（HCI）设计理念的交互式游戏应用，通过手势识别技术让用户用手指挥舞屏幕来切割水果。项目充分利用 MediaPipe 手势检测技术，实现了个性化的自适应难度调整系统。

### 项目亮点
- 🎮 **实时手势识别**：基于 MediaPipe 的摄像头实时手势检测
- 📊 **自适应系统**：根据玩家表现动态调整游戏难度
- 🎵 **沉浸式音效**：完整的游戏音效系统
- ✨ **多种游戏模式**：经典模式、禅意模式、街机模式和道场模式
- 🎨 **粒子特效**：动态的视觉反馈系统
- 📱 **响应式设计**：全屏游戏体验

## 🎮 游戏模式详解

### 1️⃣ 经典模式 (Classic)
- **难度**：中等难度
- **特点**：平衡的游戏体验，适合所有玩家
- **规则**：连续切割水果得分，碰到炸弹则游戏结束

### 2️⃣ 禅意模式 (Zen)
- **难度**：简单
- **特点**：无时间限制，无炸弹，纯粹享受游戏
- **规则**：轻松切割水果，适合放松和练习

### 3️⃣ 街机模式 (Arcade)
- **难度**：困难
- **特点**：快节奏，高强度，刺激的游戏体验
- **规则**：水果生成频率高，炸弹频繁出现

### 4️⃣ 道场模式 (Dojo)
- **难度**：进阶
- **特点**：针对性训练，挑战玩家手势控制能力
- **规则**：特定的挑战任务和训练目标

## 🖐 游戏操作说明

### 基础操作
```
短暂挥动手指     → 切割水果
自然挥动手      → 初始化校准（每局开始）
响指（OK 手势）  → 时间停止（需携带道具）
五指张开        → 清屏（全屏消除水果）
```

### 手势识别
- **切割手势**：挥动手指轨迹
- **响指手势**：食指和拇指接近
- **清屏手势**：五指完全张开

## 🧠 自适应灵敏度系统

项目采用了**智能自适应难度调整**机制，根据玩家表现动态优化游戏体验。

### 系统原理

```
游戏结束
   ↓
分析以下指标：
├─ 轨迹覆盖率（玩家活动范围）
├─ 疲劳趋势（游戏过程中的表现变化）
└─ 命中率（成功切割的比例）
   ↓
生成下一局灵敏度参数
   ↓
与上一局对比并应用新灵敏度
```

### 灵敏度调整范围
- **最小缩放**：0.78x（降低难度）
- **最大缩放**：1.38x（提高难度）
- **采样间隔**：45ms
- **校准时长**：3600ms（游戏开始时的自动校准）

### 工作原理
1. 每局游戏使用**固定的灵敏度**
2. 游戏结束后，系统收集本局数据
3. 根据玩家表现计算新灵敏度（通过 3×3 网格覆盖分析）
4. 本数据存储到浏览器本地存储（localStorage）
5. 下一局自动应用新灵敏度

## 🎯 关键游戏参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 手势保持时间 | 900ms | 触发交互需要的最短时间 |
| 清屏手势保持时间 | 420ms | 五指张开触发清屏的时间 |
| 手势冷却时间 | 700ms | 两次手势之间的间隔 |
| 响指刷新时间 | 220ms | 响指检测的刷新频率 |
| 连击窗口 | 1300ms | 两次切割被算作连击的时间窗口 |
| 时停效果持续时间 | 4100ms | 时间停止持续的毫秒数 |
| 时停冷却时间 | 7600ms | 两次时停之间的间隔 |
| 时停速度因子 | 0.04 | 时停时游戏速度的倍数 |

## 🎨 效果设置等级

系统支持三个视觉效果等级，可根据设备性能调整：

### 低等级 (Low)
- 最多 4 个同时效果
- 6 个碎片上限
- 简化阴影
- 无边缘特效

### 中等级 (Medium)
- 最多 8 个同时效果
- 12 个碎片上限
- 完整阴影
- 启用边缘特效

### 高等级 (High)
- 最多 14 个同时效果
- 20 个碎片上限
- 完整视觉效果
- 启用被动边缘特效

## 🎯 评分系统

```
基础分数    = 10 分 / 水果
连击加分    = 基础分数 × 连击数
连击步数    = 4（每4次连击增加一个倍数）
```

### 分数计算示例
- 切割 1 个水果：10 分
- 连续切割 4 个水果：40 + 额外倍数加成
- 连续切割 8 个水果：80 + 更高倍数加成

## 🎓 人机交互（HCI）设计理念

### 设计原则

#### 1. 自然交互
- 使用摄像头和手势，而非传统控制器
- 符合用户的直观理解
- 降低学习成本

#### 2. 自适应难度
- 根据玩家表现自动调整游戏难度
- 保持"心流"状态（Flow State）
- 避免过于简单或过于困难

#### 3. 实时反馈
- 即时的视觉反馈（粒子效果）
- 音效反馈（切割声、爆炸声）
- 分数和连击数提示

#### 4. 无缝体验
- 流畅的游戏画面
- 精准的手势识别
- 低延迟的响应

### 设计决策

| 决策 | 理由 | 效果 |
|------|------|------|
| 手势识别 | 更沉浸式体验 | 增加参与度 |
| 自适应系统 | 保持最优挑战 | 提高游戏时长 |
| 多个游戏模式 | 满足不同需求 | 扩大用户群体 |
| 音效反馈 | 增强代入感 | 改善游戏体验 |
| 粒子特效 | 视觉奖励 | 增加满足感 |

## 📊 性能优化

### 优化策略
1. **Canvas 优化**
   - 使用离屏 Canvas 减少重绘
   - 批量更新而非逐帧更新

2. **手势检测优化**
   - 采样间隔 45ms
   - 缓存手势数据

3. **音效优化**
   - 预加载常用音效
   - 音效复用策略

4. **特效等级**
   - 根据设备选择特效等级
   - 自动降级处理

## 🐛 常见问题解决

### Q1: 摄像头无法访问
**原因**：浏览器权限设置或硬件问题  
**解决**：
1. 检查浏览器摄像头权限
2. 重启浏览器
3. 尝试其他浏览器
4. 检查硬件摄像头是否正常

### Q2: 手势识别不准确
**原因**：光线不足或背景复杂  
**解决**：
1. 改善光线条件
2. 简化背景
3. 重新校准（挥动手进行初始化）
4. 调整摄像头位置

### Q3: 游戏卡顿
**原因**：浏览器性能不足  
**解决**：
1. 关闭其他标签页
2. 降低特效等级
3. 降低分辨率
4. 使用高性能浏览器（Chrome）

### Q4: 音效无法播放
**原因**：音频文件路径错误或浏览器限制  
**解决**：
1. 检查音频文件是否存在
2. 使用正确的文件路径
3. 在用户交互后播放音频
